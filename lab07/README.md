### Задание 1 **(2)**
*Оцените работу следующих фрагментов программ. Какие из них обладают неоднозначным поведением? Почему?*
```
int x=10, y=3;
std::cout << std::min(x=15, x+y);
```
Порядок вычисления аргументов функции не определен стандартом C++. Может быть вычислено сначала x=15, затем x+y (где x уже 15).

```
int x=10, y=3;
x=15, y+=x, x+=y;
```
Результат выполнения: x = 33, y = 18.

Неоднозначного поведения нет. Операции выполняются последовательно слева направо: сначала x = 15, затем y += x (получаем y = 18), затем x += y (получаем x = 33).

```
int x=10, y=9;
if (x>y++ && y++>9)
  cout << "yes" << endl;
cout << y;
```
Здесь нет неоднозначности, потому что оператор && гарантирует вычисление слева. Правая часть будет вычислена если, если левая будет истина

### Задание 4 **(2)**

*Почему присваивание* ```(++x)=y``` *является синтаксически правильным, а*
```(x++)=y``` - *нет? Запишите текст сообщения об ошибке, переведите и объясните его.*

```
C:/Users/лена/CLionProjects/prog4/main.cpp:4:7: error: lvalue required as left operand of assignment
    4 |     (x++) = y;
      |     ~~^~~
```
(++x) = y является синтаксически правильным, потому что префиксный инкремент ++x возвращает изменённую переменную, которой можно присвоить значение. Выражение (x++) = y некорректно, потому что постфиксный инкремент x++ возвращает старое значение переменной, которое не является изменяемым объектом для присваивания.

*Программисты на Python для обмена значений двух переменных часто пишут строку*
```
a,b = b,a
```
*Проверьте, будет ли аналогичная строка на С++ (с точкой с запятой в конце) являться синтаксически
правильной? Будет ли она обменивать значения переменных? Как в языке С++ вычисляется это выражение?*

В C++ аналогичная запись a = b, b = a; синтаксически правильна, но не выполняет обмен значениями переменных. Оператор запятая вычисляет выражения последовательно слева направо. Сначала переменной a присваивается значение b, затем переменной b присваивается уже новое значение a. В результате обе переменные получают первоначальное значение b.

### Задание 7 **(2)**

*Как работает следующая программа? Как зависит результат от исходного значения?*
```
int x;
std::cin >> x;
x-->0 && x-->0 && x-->0 && x-->0 && x-->0;
std::cout << x;
```
Программа считывает целое число x, а затем выполняет цепочку операций x-- > 0, соединённых оператором &&. Постфиксный декремент x-- сначала сравнивает текущее значение x с нулём, а затем уменьшает x на единицу. Оператор && прекращает вычисления, как только одно из условий становится ложным.
- Если исходное x больше или равно 5, все пять проверок выполняются успешно, и выводится исходное значение x - 5.
- Если исходное x равно 1, 2, 3 или 4, проверки прекращаются при достижении нуля или отрицательного значения, а выводится 0.
- Если исходное x меньше или равно 0, первая проверка ложна, и значение не изменяется.

###  Задание 9 **(3)**
*Рассмотрите следующую программу. Предполагается, что на вход подается некоторый
индекс в массиве - число от нуля до девяти и значение, которое надо записать по этому индексу.*
```
int i = 0;
std::vector<int> x(10);
std::cin >> i >> x[i];
std::cout << x[i];
```
*Проверьте работу этой программы на различных компиляторах. Найдите два компилятора (можно 
проверить онлайн компиляторы), на которых эта программа будет давать различные ответы при одинаковом
вводе. Как это объяснить?*

Программа std::cin >> i >> x[i] имеет неопределённый порядок вычислений операндов до стандарта C++17.
Ввод: 3 42
Компилятор 1 (GCC, C++17): сначала читает i=3, потом x[3]=42 → вывод 42.
Компилятор 2 (GCC, C++11 или старый MSVC): сначала вычисляет x[i] при i=0 (ссылка на x[0]), потом читает i=3, записывает 42 в x[0] → вывод 0 (значение x[3] по умолчанию).
Объяснение: в C++17 порядок операндов >> гарантирован слева направо, в C++11/14 - не определён, поэтому компилятор может вычислить x[i] до чтения нового значения i.
