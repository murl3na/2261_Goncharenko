### Задание 4 **(2)**

*Рассмотрим следующий пример в IDLE Python*
```
>>> x = 99.99
>>> int(x/10+0.001)
9
```
*Результат должен был быть равен 10, однако оказался другим. Почему так произошло?
Как исправить программу, чтобы она корректно переводила вещественные числа в целые?*

С точки зрения математики, выражение 99,99 / 10 + 0,001 действительно равно 10. Однако в Python число 99.99 хранится не как точная десятичная дробь, а как ближайшее возможное двоичное представление. Из-за этого при вычислениях итоговое значение может получиться чуть меньше 10.

Функция int() просто отбрасывает дробную часть, поэтому в результате получается 9, а не 10.

Чтобы получить корректный результат, нужно использовать функцию округления round():

```
x = 99.99
print(round(x / 10 + 0.001))  # 10
```
### Задание 5. **(2)**

*Рассмотрите следующую программу. Объясните результаты ее работы. В частности,
как величина* $y$ *повлияла на ответ?*
```
x = 1/3
y = 1
for i in range(20):
    print((x+y)-y)
    y*=10
```
*В отчете требуется привести вычисления для оценки погрешности.*

В Python значение x = 1/3 хранится не точно, а приближенно. Для типа float (аналог double) это примерно:

x = 0,3333333333333333148...

Цикл сначала прибавляет к x число y, а затем вычитает y. Если бы арифметика была идеальной, результат всегда оставался бы равным x. Но при работе с плавающей точкой при больших y сумма x + y округляется до ближайшего представимого числа. Если x окажется меньше половины шага между соседними числами в окрестности y, то добавка x просто теряется, и выражение (x + y) - y превращается в 0.

Для типа double расстояние между соседними представимыми числами порядка y примерно равно y * 2^-52. Если y = 10^k, это составляет около 10^k * 2,22 * 10^-16. Пока этот шаг существенно меньше 1/3, добавка x обычно сохраняется. Но как только шаг становится сопоставим с 1/3, результат начинает искажаться. Например, при y = 10^15 шаг равен примерно 0,222, а при y = 10^16 — уже около 2,22. В последнем случае x полностью теряется при сложении.

Таким образом, погрешность зависит не только от самого x, но и от масштаба y: чем больше y, тем грубее сетка представимых чисел вокруг суммы. Из-за округления при сложении последующее вычитание уже не может восстановить потерянные биты.



### Задание 6 **(2)**

*Для какого минимального значения* $n$ *программа на С++ выведет* **inf**? *Объясните
ответ.* *Что произойдет, если тип* **double** *заменить на* **long double**?
```
int n=...;
double s = pow(2, n);
std::cout << std::fixed << s << std::endl;
```

Минимальное значение n:

Функция pow(2, n) возвращает тип double. Максимальное значение для double примерно равно 1.8 * 10^308 (или 2^1024). При n = 1024 результат равен бесконечности (inf), так как это значение выходит за пределы допустимого диапазона. Значит, минимальное значение n = 1024.

Что произойдет при замене double на long double:

Тип long double имеет больший диапазон (обычно 80 бит или 128 бит в зависимости от компилятора). Его максимальное значение примерно равно 1.2 * 10^4932. Поэтому inf при n = 1024 не возникнет — программа выведет огромное число. Однако при дальнейшем увеличении n (примерно до 16384) результат всё равно станет бесконечностью, так как выйдет за пределы уже этого типа.

### Задание 8 **(2)**

*Какое минимальное натуральное число при преобразовании в тип* **double** *записывается с погрешностью? Объясните
ответ. Почему следующее за ним число уже выводится без погрешности?*

Минимальное натуральное число, которое при преобразовании в тип double записывается с погрешностью - это 2^53 + 1 (то есть 9007199254740993).

Объяснение:
Тип double хранит мантиссу из 52 бит, но благодаря неявной ведущей единице точность целых чисел составляет 53 бита. Это значит, что все целые числа до 2^53 (9007199254740992) представляются точно. Число 2^53 + 1 требует 54 бита, поэтому оно не может быть представлено точно и округляется до ближайшего представимого значения - 2^53 (9007199254740992).

Почему следующее число выводится без погрешности:
Следующее за ним число - 2^53 + 2 (9007199254740994). Оно чётное, и его двоичная запись укладывается в 53 бита значимых разрядов (последний бит равен нулю). Поэтому оно снова может быть представлено точно. Числа с нечётными значениями в этом диапазоне будут терять точность, а чётные - нет.
